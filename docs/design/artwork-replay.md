# Atomic artwork preparation and replay
Keep the board visible as in main. No procedural fallback even for missing paths. The decoded source image is cached only within the mounted game (one image); replay creates a fresh CanvasTexture and renderer. Abort prevents stale async tasks from writing the cache or publishing pieces. The keyed canvas host detaches the previous game immediately on replay, so asynchronous disposal cannot leave its canvas covering the next game.
Scene preparation remains nonblocking intentionally to display the board. All meshes are built hidden, laid out, then prepared in a synchronous presentation transaction on a sized canvas: validate shared map and expected count, initTexture, compile with visible meshes, pose intro, render, then emit artworkReady. The browser cannot paint between synchronous steps. On failure hide all pieces and surface existing error UI; a 20s presentation watchdog bounds waiting. Input is blocked until ready and during intro motion. Preserve sRGB, stacking and completion animation.
Tests cover missing path, delayed decode, failed image, cancellation, replay source cache/fresh texture, transaction order and failed upload/render. Browser acceptance: complete Arctic Fox Snow, click Again repeatedly; throttle asset requests on cold load, block image, retry, reduced motion, check no placeholder/old canvas and all 4/9/25 pieces appear together. CI and actual GPU/browser validation required.
